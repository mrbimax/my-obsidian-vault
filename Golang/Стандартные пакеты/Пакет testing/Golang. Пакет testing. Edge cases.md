# Golang. Пакет testing. Edge cases

## Назначение

Edge cases — это **граничные и необычные входные данные**, на которых часто проявляются ошибки.

Такие тесты проверяют не обычные сценарии, а ситуации, которые легко упустить при разработке.

---

## Зачем нужны

Например, функция работает для большинства входных данных, но падает на пустом слайсе или при очень большом числе.

Тестирование edge cases помогает обнаружить такие ошибки заранее.

## Пример

Функция:

```go
func Sum(nums []int) int {

	var sum int

	for _, n := range nums {
		sum += n
	}

	return sum

}
```

Тест:

```go
func TestSum(t *testing.T) {

	tests := []struct {
		name string
		data []int
		want int
	}{
		{"empty", []int{}, 0},
		{"one", []int{5}, 5},
		{"many", []int{1, 2, 3}, 6},
	}

	for _, tt := range tests {

		t.Run(tt.name, func(t *testing.T) {

			got := Sum(tt.data)

			if got != tt.want {
				t.Fatalf(
					"got %d, want %d",
					got,
					tt.want,
				)
			}

		})

	}

}
```

## Edge cases и Fuzzing

Edge cases:

- придумывает разработчик;
    
- проверяют известные проблемные ситуации.
    

Fuzzing:

- автоматически генерирует новые входные данные;
    
- помогает найти неизвестные edge cases.
    

Они дополняют друг друга, а не заменяют.

---

## Для собеседования

> Edge cases — это граничные и необычные входные данные, на которых часто возникают ошибки. Обычно проверяют пустые значения, `nil`, минимальные и максимальные значения, один элемент, очень большие данные и некорректный ввод. Такие тесты помогают убедиться, что функция корректно работает не только в типичных, но и в крайних сценариях.
