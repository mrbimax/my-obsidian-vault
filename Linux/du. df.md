Классическая пара утилит в Linux. Они обе измеряют дисковое пространство, но смотрят на него с абсолютно разных колоколен.

Запомнить разницу очень легко по первой букве в названии:

- **`df`** = **D**isk **F**ree (свободно на диске — смотрим общую картину по всей системе).
- **`du`** = **D**isk **U**sage (использование диска — смотрим, сколько весят конкретные папки и файлы).

## 1. `df` — Сколько места осталось на дисках?

Команда `df` опрашивает саму файловую систему. Она показывает список всех смонтированных разделов (жестких дисков, флешек, сетевых папок) и информацию о том, сколько на них занято и свободно пространства.

- **Когда использовать:** Когда вам пришел алерт «Диск заполнен на 95%» и нужно понять, какой именно раздел (или диск) забился.
- **Главный флаг:** **`-h`** (human-readable). Без него утилита выведет размеры в неудобных килобайтах. С ним — в гигабайтах (G) и мегабайтах (M).

Bash

``` bash
df -h
```

**Пример вывода:**

Plaintext

``` bash
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        50G   42G  5.5G  89% /
tmpfs           3.9G     0  3.9G   0% /dev/shm
/dev/sdb1       200G  120G   70G  64% /data
```

> **Частая проблема:** Бывает так, что `df` показывает 100% заполнение диска, но физически файлы занимают мало места. Это значит, что у вас закончились **иноды (inodes)** — индексы для файлов. Такое случается, если на диске миллионы крошечных файлов (например, сессии или кэш). Проверить это можно командой `df -i`.

## 2. `du` — Что конкретно жрет место?

Команда `du` не умеет смотреть на диски в целом. Вместо этого она берет указанную папку, начинает перебирать все файлы внутри нее один за другим и складывает их размеры.

- **Когда использовать:** Когда с помощью `df` вы выяснили, что забит корень `/`, и теперь хотите найти конкретную папку (например, тяжелые логи в `/var/log` или кэш Docker), которая сожрала всё пространство.
- **Полезные комбинации флагов:**
    - `du -sh *` — показать размер всех папок и файлов в текущей директории на одном уровне вложенности (флаг `-s` означает summary — не углубляться во все подпапки на экране).
    - `du -sh /var/log` — узнать точный вес конкретной папки.

Bash

``` bash
# Посмотреть топ-10 самых тяжелых папок в текущей директории
du -h --max-depth=1 | sort -hr | head -n 10
```

### Сводное сравнение

|Критерий|`df`|`du`|
|---|---|---|
|**Что измеряет**|Всю файловую систему / разделы диска|Конкретные файлы и папки|
|**Как считает**|Быстро берет метаданные у самой ОС|Физически сканирует (считает) каждый файл|
|**Скорость работы**|Мгновенно|Может «задуматься» на пару минут, если папка огромная|
|**Базовая команда**|`df -h`|`du -sh /путь/к/папке`|

### Почему их показания могут не совпадать? (Классический баг)

Иногда вы удаляете огромный лог-файл (например, `rm nginx.log`), запускаете `df`, а место **не освободилось**. При этом `du` честно говорит, что файла больше нет и папка пустая.

**Причина:** Какой-то процесс (в данном примере Nginx) всё еще держит этот файл открытым и продолжает писать туда данные. Для Linux файл считается удаленным только тогда, когда его никто не использует.

- **Как починить:** Перезапустить процесс, который держал файл (`systemctl restart nginx`), либо найти его через `lsof | grep deleted` и убить.
