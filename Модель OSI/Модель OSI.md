Модель **OSI** — это концептуальная модель, которая описывает, как различные сетевые протоколы и устройства взаимодействуют друг с другом для обеспечения передачи данных в сетях. Она состоит из 7 уровней, разделенных на две группы: медиа-уровни (работа с железом и кабелями) и хост-уровни (работа с данными и приложениями).

## 🔍 Подробное описание каждого уровня

### 7. Прикладной уровень (Application Layer)
* **Назначение:** Верхний уровень, обеспечивающий непосредственную связь пользовательских приложений с сетью.
* **Что делает:** Позволяет приложениям отправлять и получать информацию (например, открывать веб-страницы или скачивать файлы).
* **Ключевые протоколы:**  [[HTTP]] / [[HTTPS]] — веб-серфинг.
  * [[DNS]] — преобразование доменных имен в IP-адреса.
  * [[FTP]] — передача файлов.
  * [[SSH]] — безопасное удаленное управление.

### 6. Уровень представления (Presentation Layer)
* **Назначение:** Отвечает за то, в каком виде данные передаются по сети (синтаксис и формат).
* **Что делает:** Переводит данные из машинного формата во внутрисетевой и обратно. Здесь происходит шифрование (например, [[TLS]] / [[SSL]]) и сжатие данных (ZIP, JPEG и т.д.).
* **Пример:** Преобразование объекта в строку [[JSON]] перед отправкой.

### 5. Сеансовый уровень (Session Layer)
* **Назначение:** Управление сессиями (диалогами) между устройствами.
* **Что делает:** Устанавливает, поддерживает, синхронизирует и закрывает соединения. Если связь оборвется, сеансовый уровень поможет восстановить её с контрольной точки без повторной отправки всех данных.

### 4. Транспортный уровень (Transport Layer)
* **Назначение:** Доставка данных между конкретными процессами (портами) на устройствах.
* **Что делает:** Разбивает большие массивы данных на небольшие сегменты на стороне отправления и собирает их обратно на стороне получения.
* **Два главных протокола:**
  * [[TCP]] — надежный, с установлением соединения. Гарантирует доставку, контролирует порядок и целостность сегментов.
  * [[UDP]] — быстрый, без установления соединения. Отправляет данные «как есть», не заботясь о потере пакетов (используется в видеостриминге, играх, VoIP).

### 3. Сетевой уровень (Network Layer)
* **Назначение:** Маршрутизация данных между различными сетями.
* **Адресация:** Использует **IP-адреса** (логические адреса), которые могут динамически меняться.
* **Что делает:** Находит оптимальный путь для доставки пакета от отправителя к получателю через цепочки роутеров.
* **Главный протокол:** [[IP]] (IPv4 и IPv6). Утилита `ping` работает на этом уровне через протокол [[ICMP]].

### 2. Канальный уровень (Data Link Layer)
* **Назначение:** Передача данных внутри одной локальной сети (одного физического сегмента).
* **Адресация:** Использует **MAC-адреса** (физические адреса, жестко вшитые производителем в сетевую карту).
* **Что делает:** Упаковывает пакеты в кадры (фреймы), проверяет ошибки передачи на физическом уровне.
* **Подуровни:** 
	* *[[LLC]] (Logical Link Control) — управление логической связью.
	* [[MAC]] (Media Access Control) — управление доступом к физической среде передачи.

### 1. Физический уровень (Physical Layer)
* **Назначение:** Работа с физической средой передачи данных.
* **Что делает:** Преобразует биты (0 и 1) в электрические сигналы, световые импульсы или радиоволны и передает их по кабелю или воздуху. Никакой логики адресации здесь нет.
