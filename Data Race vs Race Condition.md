# Разница: коротко

- **Data race** — это частный случай проблемы конкурентности, связанный с небезопасным доступом к общей памяти. 

- **Race condition** — более широкое понятие: ошибка, когда результат программы зависит от порядка выполнения конкурентных операций. В Go data race можно искать через race detector, а race condition требует анализа корректности самой логики.
  
- **Data race** часто является причиной **race condition**, но не каждая **race condition** является **data race**.
```
  Race Condition 
  │ 
  ├── Data Race 
  │ 
  └── Logical race
```

---
# Как обнаруживать?
## 1. Data Race

Есть инструменты:
``` go
go run -race
//или
go test -race
```

Они ищут:
- конкурентный доступ к памяти
- отсутствие синхронизации

## 2. Race Condition

Автоматически найти сложнее.

Нужен анализ:
- архитектуры
- состояния
- порядка операций
- инвариантов системы
---
# Способы защиты от Data Race и Race Condition в Go

## Mutex

Используется для защиты критической секции:
``` go
mu.Lock()
defer mu.Unlock()

counter++
```
Когда:
- общий mutable state
- сложные операции

## Atomic

Для простых операций:
``` go
counter.Add(1)
```
Когда:
- счётчики
- флаги
- небольшие состояния

## Channel

Передача владения данными:
``` go
ch <- value
```
Идея:
> Не делить память между goroutine, а передавать данные между ними.
