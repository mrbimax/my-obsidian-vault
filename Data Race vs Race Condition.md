# Разница: коротко

- **Data race** — это частный случай проблемы конкурентности, связанный с небезопасным доступом к общей памяти. 

- **Race condition** — более широкое понятие: ошибка, когда результат программы зависит от порядка выполнения конкурентных операций. 

- **Data race** можно искать через race detector (`go run -race`)
- **Race condition** требует анализа корректности самой логики.
  
- **Data race** часто является причиной **race condition**, но не каждая **race condition** содержит **data race**.
```
  Race Condition 
  │ 
  ├── Data Race 
  │ 
  └── Logical race
```

---
# Как обнаруживать?
## 1. Data Race

Есть инструменты:
``` go
go run -race
//или
go test -race
```

Они ищут:
- конкурентный доступ к памяти
- отсутствие синхронизации

## 2. Race Condition

Автоматически найти сложнее.

Нужен анализ:
- архитектуры
- состояния
- порядка операций
- инвариантов системы

# Способы защиты от Data Race и Race Condition в Go

**1. Mutex**

```go
var (
	counter int
	mu sync.Mutex
)

go func() {
	mu.Lock()
	counter++
	mu.Unlock()
}()
```

---

**2. Atomic операции**

```go
var counter int64

atomic.AddInt64(&counter, 1)
```

---

**3. Каналы**

Вместо совместного доступа к памяти можно передавать данные через каналы.

```go
ch := make(chan int)

go func() {
	ch <- 1
}()

value := <-ch
```

# Как объяснить на собеседовании

Можно запомнить такую формулировку:

> **Data race** — две горутины одновременно обращаются к одной памяти, хотя бы одна пишет, и нет синхронизации. Это нарушение модели памяти Go, которое обнаруживает `race detector`.

> **Race condition** — результат программы зависит от порядка выполнения конкурентных операций. Это ошибка логики, и она может существовать даже при отсутствии data race, если все обращения к памяти корректно синхронизированы.

Именно поэтому `go test -race` помогает находить **data race**, но **не гарантирует обнаружение race condition**.
