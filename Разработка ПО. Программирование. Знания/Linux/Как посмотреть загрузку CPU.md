Посмотреть загрузку процессора (CPU) в Linux можно множеством способов: от быстрой сводки одной командой до детального анализа в реальном времени.

Вот лучшие инструменты, разделенные по сценариям использования.

## 1. Быстрый и детальный мониторинг в реальном времени

Для интерактивного наблюдения лучше всего подходят уже знакомые нам утилиты. Они обновляют данные каждые 1–3 секунды.

- **`htop`** — самый наглядный вариант. Просто введите `htop` в терминале. В самом верху вы увидите полосы загрузки для **каждого ядра процессора отдельно**.
    - _Цветовая индикация:_ **Синий** — низкоприоритетные процессы (nice), **Зеленый** — обычные процессы пользователя, **Красный** — системные процессы (ядро/kernel), **Серый** — виртуализация.
- **`top`** — встроенный стандарт. Запустите `top`. В верхней части обратите внимание на строку `%Cpu(s)`:
    - `us` (user) — нагрузка от ваших программ.
    - `sy` (system) — нагрузка от самого ядра Linux.
    - `id` (idle) — сколько процентов процессора **свободно** (если тут 90%, значит CPU отдыхает).
    - `wa` (iowait) — процессор простаивает, потому что ждет ответа от медленного диска или сети. _Если этот показатель высокий — тормозит диск, а не процессор._

## 2. Быстрая сводка (без запуска интерфейса)

Если вам не нужно следить за графиками, а хочется моментально узнать текущее состояние системы одной строкой.

### Утилита `uptime`

Показывает общую информацию о системе, включая **Load Average** (среднюю загрузку).

```
uptime
```

**Вывод:** `19:45:02 up 2 days, 3:12, 1 user, load average: 0.52, 0.21, 0.08`

> **Как читать Load Average:** Это три числа, которые показывают загрузку за последние **1, 5 и 15 минут** соответственно. Они измеряются в количестве процессов, ожидающих очередь на CPU. Если у вас 4 ядра, а Load Average равен `4.00` — процессор загружен ровно на 100%. Если `8.00` — система перегружена в два раза.

### Утилита `lscpu` + `uptime`

Чтобы правильно оценить Load Average, вам нужно знать количество ядер. Посмотреть их можно командой:

``` Bash
lscpu | grep "CPU(s):"
```

## 3. Профессиональный анализ (утилиты `sysstat`)

Если вам нужно глубоко разобраться, какая именно подсистема нагружает процессор (например, прерывания или виртуализация), используйте пакет `sysstat` (установка: `sudo apt install sysstat`).

### Команда `mpstat`

Показывает распределение нагрузки по всем ядрам.

``` Bash
mpstat -P ALL 1
```

_(Флаг `1` означает обновлять данные каждую секунду. Нажмите `Ctrl + C` для выхода)._

### Команда `sar`

Уникальная вещь — она умеет показывать загрузку CPU, которая была **в прошлом** (например, сегодня в 3 часа ночи, когда упал сервер), так как фоново собирает статистику.

``` Bash
# Посмотреть историю загрузки процессора за сегодня
sar -u
```

## 4. Как узнать, какой именно процесс грузит CPU?

Если вы видите, что общая загрузка 100%, выполните одну из этих команд, чтобы найти виновника:

- В `htop` или `top` процессы автоматически отсортированы по колонке `%CPU`.
- Через `ps` (разовый снимок топ-5 самых "прожорливых" процессов):
    ``` Bash
    ps -eo pid,ppid,cmd,%cpu --sort=-%cpu | head -n 6
    ```

### Шпаргалка: что выбирать?

1. Посмотреть красиво прямо сейчас: **`htop`**
2. Быстро глянуть со смартфона или слабого интернета: **`uptime`**
3. Понять, почему сервер тормозил ночью: **`sar -u`**
4. Найти процесс-вредитель в скрипте: **`ps`**
