 ## Аномалии (проблемы параллелизма)

| Аномалия                                         | Описание                                                                                      |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| **Dirty Read** (грязное чтение)                  | Чтение данных, изменённых незакоммиченной транзакцией                                         |
| **Non-repeatable Read** (неповторяющееся чтение) | Повторный SELECT той же строки даёт другое значение (кто-то закоммитил изменение)             |
| **Phantom Read** (фантомное чтение)              | Повторный SELECT по условию даёт новые строки, которых раньше не было                         |
| **Lost Update** (потерянное обновление)          | Две транзакции читают одно значение, обе пишут — одно обновление теряется                     |
| **Write Skew**                                   | Две транзакции читают пересекающиеся данные и пишут в непересекающиеся — нарушается инвариант |

## 4 стандартных уровня (SQL:1992) + 1

| Уровень | Dirty Read | Non-repeatable | Phantom |
|---|:---:|:---:|:---:|
| **Read Uncommitted** | ✅ возможен | ✅ | ✅ |
| **Read Committed** | ❌ | ✅ | ✅ |
| **Repeatable Read** | ❌ | ❌ | ✅ |
| **Serializable** | ❌ | ❌ | ❌ |

## Что реально делают СУБД

### PostgreSQL
- **Read Uncommitted** → работает как Read Committed (не поддерживает грязное чтение)
- **Read Committed** (по умолчанию) — снимок на каждый запрос
- **Repeatable Read** — снимок на всю транзакцию, ловит `serialization failure` при конфликте (защита от lost update)
- **Serializable** — SSI (Serializable Snapshot Isolation), ловит write skew

### MySQL / InnoDB
- **Read Uncommitted** — реально грязное чтение
- **Read Committed** — снимок на запрос
- **Repeatable Read** (по умолчанию) — MVCC + gap locks, защищает от фантомов (частично)
- **Serializable** — блокировки на чтение (S-locks)

### Oracle
- **Read Committed** (по умолчанию), **Serializable**
- Read Uncommitted и Repeatable Read формально есть, но маппятся на RC

### SQL Server
- Все 4 + **Snapshot** (MVCC на уровне БД)
- По умолчанию — Read Committed (с блокировками)

## Ключевые термины

- **MVCC** — многоверсионность: читатели не блокируют писателей
- **Snapshot** — снимок данных на момент времени
- **S-lock / X-lock** — shared / exclusive блокировки
- **Gap lock** — блокировка диапазона (защита от фантомов)
- **SSI** — Serializable Snapshot Isolation

## Шпаргалка выбора

- Нужна скорость, грязные данные ок → **Read Uncommitted**
- Обычная работа, по умолчанию → **Read Committed**
- Отчёты, важно постоянство чтения → **Repeatable Read**
- Финансы, критичные инварианты → **Serializable**

## Синтаксис

```sql
-- PostgreSQL
BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ;
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;

-- MySQL
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
SELECT @@transaction_isolation;

-- SQL Server
SET TRANSACTION ISOLATION LEVEL SNAPSHOT;
```

## Как запомнить

```
RU: всё грязно
RC: только закоммиченное, но может меняться
RR: строка стабильна, но фантомы летают
SZ: как будто по очереди
```
