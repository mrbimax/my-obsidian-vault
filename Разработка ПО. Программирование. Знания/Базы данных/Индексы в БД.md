## Что такое индекс

Структура данных (обычно **B-tree**), ускоряющая поиск за счёт дополнительного места и замедления записи. Аналог предметного указателя в книге.

**Trade-off:** быстрее SELECT → медленнее INSERT/UPDATE/DELETE (нужно перестраивать индекс).

## Типы индексов

| Тип | Где | Для чего |
|---|---|---|
| **B-tree** | везде (дефолт) | `=`, `<`, `>`, `BETWEEN`, `IN`, `LIKE 'abc%'`, сортировка |
| **Hash** | PostgreSQL, Memory | только `=` |
| **GIN** | PostgreSQL | массивы, JSONB, полнотекст, `@>`, `&&` |
| **GiST** | PostgreSQL | геометрия, диапазоны, KNN |
| **BRIN** | PostgreSQL | большие таблицы, коррелированные с порядком (логи, time-series) |
| **Full-text** | MySQL, SQL Server | `MATCH ... AGAINST` |
| **Spatial (R-tree)** | MySQL, PostGIS | геоданные |
| **Bitmap** | Oracle, PG (через сканирование) | низкая кардинальность (пол, статус) |
| **Clustered** | SQL Server, InnoDB (PK) | данные лежат в порядке индекса |
| **Non-clustered** | все | отдельная структура + ссылки на строки |

## Кластерный vs Некластерный

- **Clustered** — листья дерева = сами строки. Один на таблицу. В InnoDB это PRIMARY KEY.
- **Non-clustered** — листья = ссылки (ROWID / PK). Много на таблицу.

```
Clustered:     [B-tree] → [строка данных]
Non-clustered: [B-tree] → [указатель] → [строка]
```

## Составные индексы и правило левого префикса

Индекс `(a, b, c)` работает для:
- ✅ `WHERE a = ?`
- ✅ `WHERE a = ? AND b = ?`
- ✅ `WHERE a = ? AND b = ? AND c = ?`
- ✅ `WHERE a = ? ORDER BY b, c`
- ❌ `WHERE b = ?` (без `a`)
- ❌ `WHERE c = ?`

**Правило:** индекс используется слева направо, до первого пропуска.

## Покрывающий индекс (Covering)

Индекс содержит все нужные для запроса колонки → СУБД не идёт в таблицу.

```sql
CREATE INDEX idx ON users(email) INCLUDE (name);  -- PG, SQL Server
-- SELECT name FROM users WHERE email = ?  → Index Only Scan
```

## Селективность

**Селективность = уникальных значений / всего строк**

- Высокая (близко к 1) → индекс эффективен (email, id)
- Низкая (близко к 0) → индекс бесполезен (пол, boolean)

**Правило:** индекс оправдан, если отбирает **< 5-10%** строк. Иначе seq scan быстрее.

## Когда индекс НЕ используется

- `WHERE age + 1 = 10` — функция на колонке
- `WHERE LOWER(name) = 'ivan'` — нужен functional index
- `WHERE name LIKE '%ivan%'` — leading wildcard (нужен GIN/trigram)
- `WHERE name = 123` — несовпадение типов
- Маленькая таблица — дешевле seq scan
- Низкая селективность условия

**Решение:** функциональный индекс `CREATE INDEX ON users(LOWER(name));`

## Спец. виды

- **Partial / Filtered index** — индекс на части строк: `CREATE INDEX ON orders(id) WHERE status = 'active';`
- **Unique index** — гарантирует уникальность + ускоряет
- **Composite** — несколько колонок
- **Functional / Expression** — по выражению
- **Descending** — `ORDER BY x DESC`

## B-tree: как работает

```
        [50]
       /    \
   [20,35]  [70,85]
   /  |  \   /  |  \
 листья со ссылками на строки (или сами строки)
```

- Высота ~3-4 для миллионов строк
- Поиск = O(log n)
- Листья связаны в двусвязный список → range scan быстрый

## Порядок колонок в составном индексе

1. Сначала — колонки с `=` (более селективные)
2. Потом — с диапазоном (`>`, `<`, `BETWEEN`)
3. В конце — для сортировки / покрытия

```
WHERE a = ? AND b > ? AND c = ?
→ индекс (a, c, b)  лучше, чем (a, b, c)
```

## Диагностика

```sql
-- PostgreSQL
EXPLAIN (ANALYZE, BUFFERS) SELECT ...;
-- смотрим: Seq Scan / Index Scan / Index Only Scan / Bitmap

-- MySQL
EXPLAIN SELECT ...;
EXPLAIN ANALYZE SELECT ...;
-- type: ALL (плохо) → index → range → ref → eq_ref → const

-- SQL Server
SET STATISTICS IO ON;
SET SHOWPLAN_ALL ON;
```

## Управление

```sql
-- Создание
CREATE INDEX idx_name ON table(col1, col2);
CREATE INDEX CONCURRENTLY idx ON t(c);  -- PG, без блокировки
CREATE UNIQUE INDEX ...;

-- Удаление
DROP INDEX idx_name;

-- Просмотр (PG)
SELECT * FROM pg_indexes WHERE tablename = 'users';
-- неиспользуемые:
SELECT * FROM pg_stat_user_indexes WHERE idx_scan = 0;
```

## Частые ошибки

- Индекс на каждую колонку «на всякий случай» → тормозит запись
- Дублирующие индексы (`(a)` и `(a, b)`)
- Индекс на низкоселективную колонку
- Забыли про левый префикс в составном
- Не обновлена статистика (`ANALYZE`)
- Функция в WHERE ломает индекс

## Как запомнить

```
B-tree  = универсал, дефолт
Hash    = только =
GIN     = массивы/JSON/текст
GiST    = геометрия/диапазоны
BRIN    = огромные упорядоченные таблицы

Индекс = компромисс: SELECT ⬆, INSERT/UPDATE/DELETE ⬇
Селективность < 5-10% → индекс работает
```
