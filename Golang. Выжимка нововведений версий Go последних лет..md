### Go 1.18 (2022) — самый важный релиз за много лет

### Что появилось

- [[Golang. Generics|Generics]] (type parameters).
- Новый пакет `constraints`.
- Улучшенный [[fuzzing]].

### Почему это важно для backend

До 1.18 приходилось:

- писать дублирующийся код;
- использовать `interface{}` + type assertions;
- генерировать код.

После 1.18 можно писать типобезопасные:

- коллекции;
- кэши;
- middleware;
- утилиты для репозиториев/DTO.

Пример:

``` go
func Map[T any, R any](in []T, f func(T) R) []R {
    out := make([]R, len(in))
    for i, v := range in {
        out[i] = f(v)
    }
    return out
}
```

### Go 1.19 (2022)

### Ключевое

- Улучшения GC и управления памятью.
- Более предсказуемые паузы.

### Что сказать на интервью

Для высоконагруженных сервисов это дало снижение memory overhead и более стабильные latency-профили.

### Go 1.20 (2023)

### Важные вещи

- PGO (Profile-Guided Optimization).
- `errors.Join`.
- `context.WithCancelCause`.

### Почему это важно

PGO — компилятор может оптимизировать код на основе реальных профилей продакшена.

CancelCause:

``` go
ctx, cancel := context.WithCancelCause(context.Background())
cancel(errors.New("upstream timeout"))

err := context.Cause(ctx)
```

Это очень полезно для:

- tracing;
- observability;
- диагностики отменённых запросов.

### Go 1.21 (2023)

### Ключевые изменения

- Появился пакет `slices`.
- Пакет `maps`.
- Улучшен вывод типов для generics.
- Новый механизм управления версией языка в `go.mod`.

### Что особенно любят спрашивать

`slices.Sort`, `slices.Contains`, `slices.Clone` — теперь это стандартный способ работы со слайсами.

``` go
slices.Sort(nums)
ok := slices.Contains(nums, 42)
```

### Go 1.22 (2024) — очень важный для корректности

### Главная фича: новая семантика `for range`

Раньше была классическая ловушка:

``` go
for _, v := range items {
    go func() {
        fmt.Println(v) // могло печатать последнее значение
    }()
}
```

В Go 1.22 переменная цикла создаётся заново на каждой итерации, и этот баг исчезает.

### Как это сформулировать

Это одно из самых практичных изменений: оно устранило целый класс concurrency-багов, которые регулярно встречались в goroutine-коде.

Также появились:

- `for i := range 10`;
- улучшения производительности `defer`.

### Go 1.23 (2024)

### Что стоит упомянуть

- Новый пакет `iter` и поддержка iterator-паттернов.
- Дополнительные оптимизации runtime и компилятора.
- Улучшения garbage collector и scheduler.

### Для backend

Итераторы пока не так массово используются, как generics, но они открывают путь к более ленивой обработке данных и потоковым API.

### Go 1.24 (2025)

Если собеседование в 2026 — можно сказать осторожно:

В 1.24 продолжается тренд на улучшение производительности компиляции, runtime и стандартной библиотеки; для прикладного backend-кода изменения менее революционные, чем generics или новая семантика range.

Это безопасная формулировка, даже если интервьюер сам следит за релизами.
